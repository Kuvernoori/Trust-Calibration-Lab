# Trust Calibration Lab — deployment guide

This prototype is split into two deployable applications:

- `frontend/` — static Vite build, deploy to Vercel, Netlify, Cloudflare Pages, or any static host.
- `backend/TrustCalibrationLab.Api/` — ASP.NET Core API, deploy to Render, Fly.io, Azure App Service, or another .NET host.

Railway is not required.

## Recommended setup: Vercel + Render

### 1. Push the repository to GitHub

Create a repository and push the project root. Do not commit `backend/TrustCalibrationLab.Api/trust-calibration-lab.db`, `frontend/node_modules/`, or `frontend/dist/`.

From the project root:

```powershell
git init
git add .
git commit -m "Prepare Trust Calibration Lab for deployment"
git branch -M main
git remote add origin https://github.com/<your-account>/<your-repository>.git
git push -u origin main
```

### 2. Deploy the API to Render

1. Open [render.com](https://render.com), create a Web Service, and connect the GitHub repository.
2. Leave **Root Directory** empty (repository root).
3. Choose **Docker** as the runtime. Render will use the root [Dockerfile](./Dockerfile).
4. If Render asks for a Dockerfile path, enter `Dockerfile`.
5. Set the health check path to `/api/health`.
6. Deploy. Copy the generated API URL, for example `https://trust-calibration-api.onrender.com`.
7. Add an environment variable:

```text
Cors__Origins=https://<your-vercel-project>.vercel.app
```

For a single frontend domain, the Render environment variable should be entered as one value exactly as shown above. The API also accepts multiple origins separated by commas. Do not include a trailing slash:

```text
https://frontend-dun-six-58.vercel.app
```

For Vercel, use the real Render service URL without a trailing slash:

```text
https://trust-calibration-lab.onrender.com
```

After changing either variable, redeploy both services. First verify the API directly at `/api/health`; if that URL does not return HTTP 200, the issue is in Render (service name, failed deployment, sleeping/paused service, or port configuration), not in CORS or Vercel.

The double underscore maps to the ASP.NET configuration section `Cors:Origins`. If you add a custom frontend domain, use that exact HTTPS origin instead.

#### SQLite limitation

The prototype uses a local SQLite file. On hosts with an ephemeral filesystem, data can be lost after a redeploy or instance restart. For a classroom demo, use a persistent disk where the host offers one and mount it at the API working directory. For a durable multi-user deployment, replace SQLite with PostgreSQL and set `ConnectionStrings__Default` to the hosted database connection string.

### 3. Deploy the frontend to Vercel

1. Open [vercel.com](https://vercel.com) and import the same GitHub repository.
2. Set **Root Directory** to `frontend`.
3. Vercel should detect Vite automatically. The build command is `npm run build`; the output directory is `dist`.
4. In **Settings → Environment Variables**, add this variable before deploying:

```text
VITE_API_BASE_URL=https://trust-calibration-api.onrender.com
```

In the Vercel form, enter the fields separately:

```text
Name:  VITE_API_BASE_URL
Value: https://trust-calibration-api.onrender.com
```

Replace the value with the real URL generated by Render. Do not append `/api` and do not add a trailing slash. Select at least **Production**; selecting **Preview** as well is useful when testing Vercel preview deployments. The file [frontend/.env.example](./frontend/.env.example) is only a template and is not uploaded to Vercel automatically. You can create `frontend/.env.local` for local standalone preview, but never commit secrets or private credentials.

5. Deploy the frontend.
6. Copy the final Vercel URL and replace the Render `Cors__Origins` value with it if the URL changed.
7. Redeploy the API after changing CORS.

#### If Vercel reports `node_modules/.bin/tsc: Permission denied`

This means generated dependencies were committed to Git or were uploaded with incorrect executable permissions. `node_modules` must never be committed. From the repository root, run:

```powershell
git rm -r --cached frontend/node_modules frontend/dist
git add .gitignore frontend/package-lock.json frontend/package.json
git commit -m "Fix frontend deployment artifacts"
git push
```

If Git reports that either path is not tracked, remove that path from the command and continue. In Vercel, confirm **Root Directory** is exactly `frontend`, then choose **Redeploy** with cache disabled if that option is shown. Vercel should install from `frontend/package-lock.json` on a clean Linux build machine.

### 4. Verify the deployment

Open these URLs:

```text
https://<api-host>/
https://<api-host>/api/health
https://<api-host>/api/cases
https://<frontend-host>/
```

In the browser, open a case, evaluate one comment, reload the page, and confirm the draft is still available. Complete a review and confirm the results page opens. Check the browser Network panel for failed CORS or `/api` requests.

## Alternative: Azure

For a Microsoft-hosted setup, create an Azure App Service for the backend using the .NET 10 runtime or deploy the included Dockerfile to an Azure Web App for Containers. Deploy the Vite `dist/` folder to Azure Static Web Apps or another static host. Set `VITE_API_BASE_URL` to the App Service URL and configure the App Service setting `Cors__Origins` to the Static Web App URL.

## Local production-like test

Build the frontend:

```powershell
cd frontend
npm ci
npm run build
npm run preview
```

Build and run the API:

```powershell
cd backend/TrustCalibrationLab.Api
dotnet restore
dotnet publish -c Release -o ./publish
$env:ASPNETCORE_URLS = "http://localhost:5070"
dotnet ./publish/TrustCalibrationLab.Api.dll
```

For this local test leave `VITE_API_BASE_URL` empty only when using the Vite development proxy. A preview server is not automatically configured with that proxy, so set `VITE_API_BASE_URL=http://localhost:5070` before building a standalone preview.

## Deployment checklist

- .NET 10 SDK/runtime or the .NET 10 Docker image is available.
- The API health check returns HTTP 200.
- `Cors__Origins` contains the exact frontend origin, with no trailing slash.
- `VITE_API_BASE_URL` points to the API origin, not `/api`.
- The SQLite persistence limitation is acceptable for the demo.
- No answer key or local database file is committed to Git.
- Browser Network requests reach the deployed API without CORS errors.
